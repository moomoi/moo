# moo.moi

`web/` is the moo.moi site, built with [Orbit](https://github.com/tishlang/orbit), the markdown-first
Tish framework. Every page is prerendered to static HTML. `/callback`, the sign-in relay, is the one
route rendered per request, as a Node function on Vercel. Pages ship no script.

## Editing the site

| Path | What it is |
| --- | --- |
| `orbit.config.tish` | Site metadata, the docs collection, redirects (`/download`) |
| `pages/` | One file per route. `_layout.tish` is the nav, footer and background; `index`, `get`, `marketplace/index` and `marketplace/[id]`, `legal/*`, `docs/index` and `docs/[slug]`, `404`, `callback` |
| `lib/` | Shared pieces: `ui` (hero, the home page's launcher demo), `icons`, `docs` (sidebar), `legal`, `plugins` (the marketplace list), `links` |
| `content/docs/` | The user docs, one markdown file per page |
| `styles/site.css` | The stylesheet (Orbit's Tailwind preflight is off) |
| `public/` | Logo and favicon (generated by `scripts/make-icons.sh`) |

Pages export `page(ctx, props)`, and optionally `head`, `load` and `paths`, as the
[Orbit README](https://github.com/tishlang/orbit#readme) describes. To add a page, add a file under `pages/`.

| Path | Response |
| --- | --- |
| `/` | Landing page |
| `/get` | Download page (the button goes to `/download`) |
| `/download` | `302` to the latest DMG on GitHub (a redirect in `orbit.config.tish`) |
| `/docs`, `/docs/<page>` | User documentation (below) |
| `/marketplace` | Plugin marketplace (the `PLUGINS` list in `lib/plugins.tish`) |
| `/marketplace/<id>` | A plugin's page; Install opens `moo://plugins/<id>` |
| `/legal`, `/legal/terms`, `/legal/privacy` | Legal pages |
| `/callback` | Sign-in relay (below) |
| `/sitemap.xml`, `/robots.txt` | Generated by Orbit |
| anything else | 404 page |

## The sign-in relay

Hypery only redirects to registered URLs, and the Moo app (`app_1791139621564_l2l6kzx0m`) has
exactly one: `https://moo.moi/callback`. Moo signs in like this:

1. Moo listens on `127.0.0.1:<free port>` and opens Hypery's authorize page with
   `redirect_uri=https://moo.moi/callback`, a PKCE challenge, and `state=<port>.<nonce>`.
2. Hypery sends the browser to `https://moo.moi/callback?code=…&state=…`.
3. `pages/callback.tish` checks that `state` is a port from 1024 to 65535, a dot, and a 16–128 character
   base64url nonce, then answers `302` to `http://127.0.0.1:<port>/callback?<the same query>`
   with `Cache-Control: no-store` and `Referrer-Policy: no-referrer`. Anything else gets a 400
   page. Error callbacks (`error=access_denied`) are relayed the same way so Moo can report them.
4. Moo checks the whole `state` and exchanges the code, sending the same `redirect_uri` and its
   PKCE verifier.

The server keeps no state and logs nothing about requests. A code passing through it can't be
redeemed without the verifier, which never leaves the Mac.

Moo picks the redirect from the provider's `redirectUri` in `shortcuts.json`, then
`MOO_HYPERY_REDIRECT`, then the built-in `https://moo.moi/callback`. The client id comes from
`MOO_HYPERY_CLIENT_ID` or the built-in one.

## Docs

The user docs are markdown files in `web/content/docs/`, an Orbit collection. Each starts with
frontmatter:

```yaml
---
title: Install
description: One line under the title and on the docs home.
slug: install
section: Getting started
order: 1
---
```

`slug` is the URL (`/docs/install`), `section` groups pages in the sidebar and on the docs home, and
`order` is the reading order. Keys are inline HTML: `<kbd>⌘</kbd> <kbd>K</kbd>`.

## Build and run

```sh
cd web && npm ci
npm run dev                        # http://localhost:3000, reloads on edits
npm run build                      # .orbit/ locally; .vercel/output on Vercel
npm start                          # serve a local build
```

To try a sign-in against a local copy, point Moo at it:
`MOO_HYPERY_REDIRECT=http://127.0.0.1:3000/callback`. That URL must also be registered with the
OAuth app, so for real Hypery this only works with `https://moo.moi/callback`.

## Deploy

moo.moi is the Vercel project `moo-web` (team Knoeone), connected to this repo with `web/` as its
root: every push to `main` deploys production, and every PR gets a preview deployment (the
**Vercel** check on the PR). `web/vercel.json` runs `npm ci` and `npm run build`. On Vercel,
`orbit build` writes the Build Output API (`.vercel/output`): the static pages and one function for
`/callback`. Preview deployments sit behind Vercel's login; test them with
`vercel curl /callback --deployment <url>`.
